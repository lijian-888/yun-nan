# 国家水稻数据中心审定指标查询

本功能面向**全量品种和全部审定记录**，不是针对某个品种写规则。已有的
`rice_variety_trait_measurement`（59 类指标）、`rice_variety_yield_observation`
（亩产试验观测）继续作为主要结构化证据；批量 ETL 只补充原先遗漏在
`rice_variety_approval` 的产量表现等叙述字段中的显式数值。

## 批量处理

使用迁移数据库账号设置 `MIGRATION_DATABASE_URL`，然后在 API 代码环境执行：

```text
python -m app.ricedata_trait_etl
python -m app.ricedata_trait_etl --apply
```

第一条只读预检，第二条按 250 条审定记录一批幂等写入。可以用
`--variety-id <ID>` 做小范围复核。作业记录在
`ricedata.rice_variety_narrative_parse_status`；抽取值在
`ricedata.rice_variety_narrative_fact`。每条值保留审定 ID、来源字段、
原句、原文哈希、近似词、解析版本和审核状态。重新执行会刷新本版本的
机器抽取记录，不覆盖 `verified` 人工审核行。

2026-10-09 本地全量预检：33,784 个品种、37,321 条审定记录、76,093
个非空补充叙述字段，新增识别 1,662 个数值事实。这是对已有结构化
数据的**补充**，不是说全部 37,321 条记录都含新增数值。

## 对话行为

精确指标问题直接查询数据库，不调用模型猜数值。先按品种 ID／完整名称／
别名定位；若有多条审定记录而用户未指明省份、年份或审定编号，先追问。
用户选定后只在该审定下查询。遇到多个试验值逐项列出、保留试验上下文，
不擅自平均；没有已结构化数值时明确说明，不挪用其他审定的值。

## 数据质量边界

抽取器只接受明确的“指标名 + 数字 + 单位/近似词”模式。OCR 错字、
隐含比较、无法确定指标归属的数字不自动成为事实。例如“每穗实粒数粒120粒”
需人工核对。`machine_extracted` 结果在用户界面显示原句；重要科研结论
应按 `review_status` 完成人工复核。后续爬取增量可重复执行 ETL。

部署顺序：先在目标数据库运行 ETL 建表并填充，再重建／重启 API，
使最小权限应用角色获得新表只读授权。数据库现有原始记录不被改写。
