# 表型辅助亲本推荐业务与开发规格

状态：已确认  
适用范围：云南省农业科学院水稻育种智能体第一期试用版  
候选数据边界：仅国家水稻数据中心种质

## 1. 功能定位

本模块根据科研人员确认的育种目标，使用国家水稻数据中心已经入库的品种、审定、性状、产量和系谱证据，生成可解释的亲本组合辅助推荐。

系统输出的是“基于现有表型和系谱证据的候选组合优先级”，不是后代表现预测、配合力预测、育种值估计或成功率承诺。第一期不使用院内育种材料作为候选，不使用基因型预测，也不管理杂交试验和后代记录。

## 2. 使用流程

1. 科研人员选择推荐模式：常规稻杂交或杂交稻配组。
2. 科研人员用自然语言填写育种目标。
3. 大模型只负责把育种目标解析为结构化草稿；科研人员确认后才生效。
4. 系统只展示通过字段白名单校验的条件草稿；科研人员修改并明确确认后才允许执行。
5. 规则引擎仅从国家水稻数据中心检索候选品种。
6. 系统依次执行身份与角色检查、硬门槛、证据状态判断和候选召回。
7. 系统形成单亲本档案，并生成角色兼容的亲本组合。
8. 系统计算三代或五代内共同祖先、直接亲缘和系谱完整度。
9. 系统评价目标覆盖、性状互补、环境适配、证据可信度和风险。
10. 结果按 A、B、C、待核实、已排除分级展示。
11. 指定育种专家对组合执行接受、暂缓或否决。
12. 系统保存不可变推荐快照，并支持导出报告。

## 3. 推荐模式

### 3.1 常规稻杂交

- 第一阶段不区分 A×B 与 B×A 的评分。
- 科研人员可以指定杂交方向；指定后按母本、父本范围执行条件。
- 不得把组合评分解释为后代性状概率。

### 3.2 杂交稻配组

- 第一期支持三系不育系×恢复系、两系不育系×恢复系。
- 亲本角色是硬门槛，角色不兼容的组合进入“已排除”。
- 数据库不能证明花期相遇或恢复关系时，生成待核实事项，不虚构为符合。
- A×B 保持系配组不在第一期范围内。

## 4. 育种目标和条件

### 4.1 条件结构

每个条件必须包含：

- 条件名称；
- 作用范围：每个亲本、至少一个亲本、母本、父本或整个组合；
- 数据字段或性状；
- 比较符；
- 目标值、范围、等级或集合；
- 单位；
- 条件类型：硬门槛或排序偏好；
- 证据缺失处理方式；
- 数据来源和适用推荐模式。

### 4.2 大模型目标理解

第一期不使用预设条件模板。科研人员直接描述育种目标，大模型只可从下列数据库支持范围生成条件草稿：

- 籼粳类型、常规/杂交类型和亲本角色；
- 生育期范围；
- 株高范围；
- 目标地区或适宜地区证据；
- 相对对照增产阈值；
- 指定病害及抗性等级；
- 抗倒伏；
- 品质等级或明确品质指标；
- 至少一个亲本提供指定优势性状；
- 三代或五代内共同祖先限制；
- 数据库能够直接判断的亲本角色和明确性状指标。

大模型不得编造用户未给出的阈值。笼统的“高产、优质、抗病”等目标必须进入未解决事项，引导科研人员补充阈值；不能静默转成系统默认值。大模型生成的草稿必须保存解析记录，并经当前用户确认后才能创建推荐任务。

### 4.3 自定义条件

正式入口为自然语言描述，由大模型生成结构化草稿；科研人员可在草稿上修改字段、运算符、阈值、单位、条件性质和作用范围。

自然语言草稿必须经用户确认。无法映射到受支持字段的条件不得静默忽略，应转换为待核实事项或提示当前无法执行。

### 4.4 三态判定

每个条件只允许三种证据结论：

- 通过：存在满足条件的有效证据；
- 不通过：存在明确违反条件的有效证据；
- 未知：证据缺失、冲突、范围不适用或质量不足。

“未知”不等于“通过”，也不等于“不通过”。普通硬门槛为未知时进入待核实；如果用户选择“必须有证据”，未知即不能进入正式推荐。

## 5. 硬门槛和偏好权重

硬门槛决定组合有没有资格进入 A、B、C 推荐等级；其他高分不能抵消硬门槛失败。适合配置为硬门槛的条件包括：

- 籼粳和品种类型；
- 杂交稻亲本角色；
- 明确的生育期范围；
- 指定病害最低抗性等级；
- 明确品质等级或指标；
- 三代或五代共同祖先限制；
- 科研人员明确要求的地区适应证据；
- 必须具备的证据或材料可获得性。

偏好权重只对已经通过硬门槛的候选进行排序。普通界面使用“关键、重要、一般”三个重要度，系统映射为固定权重；高级界面才开放数值权重。权重由专家配置，大模型不得自行产生最终权重。

## 6. 数据证据规则

### 6.1 数据支持矩阵

| 业务需要 | 主要数据库来源 | 第一期开发表达 |
|---|---|---|
| 品种身份、名称、类型、亲本来源 | `ricedata.rice_variety` | 候选身份与基础过滤 |
| 审定年份、地区、审定号和说明 | `ricedata.rice_variety_approval` | 地区、生育期、品质和抗性证据上下文 |
| 结构化性状数值 | `ricedata.rice_variety_trait_summary`、`rice_variety_trait_measurement` | 生育期、株高、品质等条件判断 |
| 审定文字抽取性状 | `ricedata.rice_variety_narrative_fact` | 仅使用保留来源和复核状态的事实 |
| 产量试验记录 | `ricedata.rice_variety_yield_observation` | 同一试验内相对对照评价 |
| 系谱快照、节点和边 | `ricedata.rice_pedigree_snapshot`、`rice_pedigree_node`、`rice_pedigree_edge` | 祖先路径和亲缘风险 |
| 原始网页 | 品种及审定记录的 `source_url` | 结果追溯和人工核对 |

院内 `core.material`、`agent_data` 或导入层数据不进入第一期候选召回、筛选、评分或配组。

### 6.2 证据等级

同一候选的证据按以下原则处理：

1. 目标地区、品种自身、正式审定或已核验结构化数据优先；
2. 其他地区的正式审定证据可以辅助，但降低环境匹配度；
3. 机器抽取且未核验的数据只能用于候选发现或提示，不单独支持严格硬门槛；
4. 后代或历史组合表现属于间接证据，不回填为亲本自身表型；
5. 只有文字描述且缺少年份、地区或试验上下文时降低可信度；
6. 缺失数据保留为未知，不用平均值、默认值或大模型猜测补齐。

### 6.3 产量与稳产

- 优先使用同一试验中的相对对照增减产，不能直接横向比较不同地区、年份和试验类型的绝对亩产。
- 区域试验、生产试验和品种比较试验分开统计。
- 年度记录与多年汇总不得重复计数。
- 稳产性至少需要多个可比较记录；只有单个记录时不得声称稳产。
- 处于待复核状态的产量抽取结果不能单独作为硬门槛依据。

### 6.4 病害、品质与冲突记录

- 抗病硬门槛必须指定病害和等级，不能使用笼统“抗病性好”。
- 品质硬门槛必须指定等级或具体指标，不能以模糊综合印象代替。
- 同一目标地区存在多个有效抗病记录时，硬门槛按最不利有效记录判断；评分同时展示最好、平均和最差证据。
- 其他地区的不利记录形成风险提示，并降低可信度。
- 单位、量纲、等级体系或试验上下文不可比较时，标记为未知或冲突。

## 7. 候选召回和人工干预

- 系统在国家水稻数据中心全库中自动检索，先使用可索引的硬条件缩小候选，再加载详细证据。
- 科研人员可以把国家水稻数据中心品种加入必评名单、重点关注或排除名单。
- 必评只保证进入评价，不能绕过硬门槛、角色检查或亲缘检查。
- 页面必须解释品种未被召回、被排除或进入待核实的原因。
- 材料可获得性采用“可获得、不可获得、未知”三态人工记录；未知不冒充可获得。

## 8. 系谱和三代、五代近亲判断

### 8.1 计算口径

对每个候选亲本，从已经核验的根节点沿“子代→亲本”方向向上遍历，并记录每个祖先距当前候选的最短代数：

- 亲本为第 1 代祖先；
- 祖父母为第 2 代祖先；
- 依次扩展到用户选择的第 3 代或第 5 代。

比较双亲祖先集合：

- 同一品种或已确认别名：排除；
- 亲本—子代关系：排除；
- 共同父本或共同母本：排除；
- 两代内共同祖先：排除；
- 三代内共同祖先：默认高风险并排除，科研人员可在本次任务中明确调整；
- 四至五代共同祖先：默认风险提示和扣分，用户选择“五代内排除”时排除；
- 没有共同祖先但任一系谱不完整：结论为“亲缘未知”，不能表述为“无亲缘”。

祖先身份只使用数据库中已链接的品种标识或已经确认的身份映射；相同文字名称但身份未确认时形成疑似共同祖先，进入待核实，不能直接合并。

### 8.2 输出内容

亲缘结果必须包含：

- 最近共同祖先；
- 共同祖先距双亲的代数；
- 双方各自到共同祖先的路径；
- 三代或五代范围是否完整；
- 亲缘风险等级；
- 数据缺口和原始系谱来源。

第一期不把简化路径结果称为正式谱系亲缘系数或近交系数。

## 9. 组合评价和结果分级

通过硬门槛后，组合评价考虑：

- 目标性状满足度；
- 双亲性状互补度；
- 目标地区证据匹配度；
- 产量和稳产证据；
- 系谱多样性及未知风险；
- 数据覆盖度和证据可信度；
- 双亲共同严重缺陷；
- 杂交稻角色兼容性。

目标匹配度、证据覆盖度、可信度和亲缘风险必须分别显示，不能压缩成一个无法解释的总分。结果分级为：

- A 级：硬门槛通过，目标覆盖和证据可信度较高，优先推荐；
- B 级：硬门槛通过，整体可考虑，但存在次要短板；
- C 级：硬门槛通过，具有探索价值但证据或互补性较弱；
- 待核实：关键条件为未知，完成核实前不进入正式推荐；
- 已排除：至少一个硬门槛明确不通过。

等级内部按目标匹配度排序。默认展示前 10 个正式推荐组合、备选组合、待核实组合和带原因的排除记录。

## 10. 结果解释、审核和留存

每个组合必须展示：

- 推荐原因；
- 逐条说明组合通过了哪些硬门槛、命中了哪些排序偏好；
- 双亲各自贡献的目标性状；
- 通过、不通过和未知的条件；
- 优势、共同缺陷和风险；
- 已知共同祖先和亲缘路径；
- 适宜地区和生育期证据；
- 数据来源和原始网页链接；
- 推荐等级、目标匹配度、覆盖度和可信度；
- 待人工确认事项。

正式推荐组合还必须提供双亲五性评价对照，分别展示丰产、稳产、抗病、耐逆和品质的已有得分、缺失维度、证据覆盖情况及单亲综合评价状态。组合层面只说明某一维度由母本、父本、双方或均无证据覆盖，不对双亲分数求平均，也不生成所谓后代五性综合分。科研人员可以从组合卡片打开任一亲本的完整品种档案，查看基本信息、审定记录、性状、产量、适宜地区、系谱摘要及原始网页来源。

普通科研人员可以创建任务和保存草稿。具有育种审核权限的人员可以接受、暂缓或否决组合并填写意见。字段管理员不自动具有育种审核权限。

专家确认后的推荐快照不可被后续数据库更新自动改写。数据更新时提示用户重新分析，并产生新版本。导出至少支持 PDF 和表格格式。

## 11. 系统实现边界

- 大模型：解析自然语言目标、生成结构化条件草稿、根据确定性结果形成易读说明。
- 规则引擎：执行硬门槛、三态判断、证据分级、组合生成、评分和等级划分。
- 系谱算法：执行有界祖先遍历、共同祖先和路径计算、完整度判断。
- PostgreSQL：保存目标解析草稿、用户确认条件、任务、证据引用、推荐快照、人工核实和专家决策。
- 前端：目标填写、条件草稿确认、候选范围、证据卡、系谱路径、分级结果和审核操作。

大模型不得直接查询任意表、决定权重、绕过硬门槛、推断缺失性状或直接批准最终组合。第一期不需要用现有数据微调或训练大模型。

## 12. 状态和数据留存

推荐任务状态：草稿、已生成、待核实、已审核。  
组合专家决策：接受、暂缓、否决。  

每个推荐快照至少保存：原始目标、大模型结构化草稿、用户确认条件、推荐模式、候选来源和候选标识、证据记录标识、规则版本、算法版本、各项判定、结果等级、专家操作、时间和操作者。

## 13. 验收标准

由农科院提供 20～30 个历史或专家设计案例，至少验证：

1. 角色不兼容组合不会进入正式推荐；
2. 已知违反硬门槛的组合不会被其他高分补回；
3. 经人工核对的三代、五代共同祖先和路径计算正确；
4. 每个事实结论均可追溯到具体数据库记录或原始网页；
5. 专家认可的组合能够进入前 10 或合理推荐等级；
6. 证据缺失和冲突明确展示，不产生虚构结论；
7. 专家否决结果能够定位到规则、数据、亲缘风险或证据不足原因。

这些案例用于规则校准、回归测试和项目验收，不用于训练大模型。

## 14. 推荐开发顺序

1. 建立目标解析草稿、用户确认条件、任务、候选、证据、组合、审核和快照数据模型。
2. 建立 RiceData 候选检索和单品种证据档案接口。
3. 实现条件三态判定和硬门槛执行器。
4. 实现三代、五代祖先遍历和共同祖先路径算法。
5. 实现常规稻组合生成、互补评价和结果分级。
6. 实现杂交稻角色兼容及人工核实流程。
7. 实现自然语言目标入口、草稿确认、结果解释和专家审核。
8. 实现快照、版本、PDF/表格导出和审计记录。
9. 使用 20～30 个专家案例校准规则并完成验收。
